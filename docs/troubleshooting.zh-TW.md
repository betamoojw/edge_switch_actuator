# 疑難排解與復原

先記下韌體版本、運作時間、所選協定、故障碼、通道狀態與最後操作；若知道映像檔雜湊也一併記錄。認證資訊、原始核心傾印及組態匯出請私下保管。[檢查紀錄](live-verification.md)說明只看畫面的限制。

| 狀況 | 優先檢查 | 後續處理 |
| --- | --- | --- |
| 無法存取裝置 | 電源、網路、分配位址、AP/STA 連線 | 設定用位址僅供連上本機 AP 時使用，不要先重設已設定裝置 |
| 登入遭拒 | 裝置及帳號、專屬設定密碼或既有密碼 | 閱讀[認證資訊復原](device-credentials.md)，原廠重設會清除設定 |
| ON 無法使用或遭拒 | 角色、通道遮罩、啟用與鎖定 | 請安裝人員核對策略，不要改用其他協定繞過鎖定 |
| 畫面 ON，負載未動作 | 狀態只是命令回報 | 隔離後由合格人員查驗配線、接點與負載，勿把標示當作安全隔離證據 |
| 脈衝提早結束 | 設定時間、後續命令、停用及斷線策略 | 比對活動及全部命令來源，一般命令可取消計時 |
| `waiting_network` | 上行介面是否有可用 IPv4 | 單獨 AP 連線不符合 TCP/KNX/MCP 要求 |
| RTU 逾時 | 站號、鮑率、同位檢查、A/B、終端電阻與模式 | 先讀取，檢查 CRC、訊框計數及主站配線 |
| TCP 逾時 | 模式、上行位址、連接埠、對端限制及防火牆 | 確認路由與用戶端數量，閒置連線在 60 秒後關閉 |
| KNX 修改衝突 | 目前修訂號及擁有者 | 重新載入並整合修改，不可逕行覆蓋 ETS 下載 |
| KNX 顯示 401、控制項停用 | 瀏覽器認證是否仍有效 | 重新登入並載入快照，見[網頁接管範例](knx-address-entry.md#taking-over-for-web-editing) |
| HA 實體消失或未更新 | MQTT 狀態、探索、前綴及代理 ACL | 查看保留探索資訊與 HA birth 主題，見 [HA 指南](home-assistant.md) |
| 沒有 MCP 選單 | 執行中映像及內嵌介面的功能 | 版本字串不足以識別編譯選項，須核對映像檔 |
| MCP 等待時間或反覆重試 | NTP、DNS、上行及端點 | 參阅[MCP 排解](xiaozhi-mcp.md#runtime-and-troubleshooting)，勿停用 TLS 驗證 |
| GitHub 更新清單異常 | 韌體版本、GitHub 連線/流量限制及發行檔案 | 0.6.4 已修正網址，但檔案比對仍寬鬆；手動使用核對過的 `_ota.bin` |
| RGB 測試無顯示或蜂鳴器無聲 | 啟用狀態與優先序 | 故障/程式設定/重設可能蓋過測試，蜂鳴器須先啟用 |

## 設定與復原範圍 { #configuration-and-recovery-boundaries }

致動器、KNX、MCP 使用經驗證的多代儲存。通用網路、帳號與框架整合設定仍原地寫入 JSON，斷電韌性不同。這是原始碼觀察，並非已完成斷電測試。請另行保管網路、帳號、繼電器策略、整合與 KNX 關聯設定。

使用內嵌介面的手動 OTA，設計上會保留檔案系統設定，但不是備份機制。上傳檔案系統、完整清除、不相容降版或原廠重設可能造成資料遺失。更新前保留映像識別、對應 ELF 並規劃本機復原。

原廠重設清除使用者設定與 KNX 組態，但保留製造時的設定身份。BOOT 按住十秒也會重設；停用點擊動作不會取消長按。之後以裝置專屬密碼重新設定。無法開機時，隔離負載並依板卡 USB 下載模式與[首次燒錄步驟](gettingstarted.md#3-build-and-flash-a-unit)復原。燒錄是主動維護，不屬於診斷讀取。

## 如何提供有效問題報告 { #useful-support-report }

附上板卡版本、韌體版本/雜湊、瀏覽器版本、所選協定、去識別截圖、預期與實際行為、重現步驟及模擬器是否重現。可提供故障碼、計數與時間戳，但移除網路密碼、權杖、設定 QR 標籤、端點查詢參數及多餘的裝置身份資訊。已知問題請連到對應原始碼審查，不宜直接判定硬體故障。
