# 故障排查与恢复

先记录固件版本、运行时间、当前协议、故障码、通道状态及最近操作；已知时附上镜像哈希。凭据、原始核心转储和配置导出应私下保存。[检查记录](live-verification.md)说明仅观察界面的局限。

| 现象 | 首先检查 | 下一步 |
| --- | --- | --- |
| 无法访问设备 | 供电、网络、路由器分配地址、AP/STA | 仅连接本机 AP 时使用配网地址，不要首先复位已调试设备 |
| 登录失败 | 设备和账号是否正确，设置密码还是已保存密码 | 参见[凭据恢复](device-credentials.md)，出厂复位会删除配置 |
| ON 不可用或被拒绝 | 角色、通道掩码、启用与锁定 | 请安装人员检查策略，不要换协议绕过锁定 |
| 界面 ON，负载未启动 | 状态仅代表命令 | 隔离后由合格人员检查配线、触点及负载；状态标记不能证明安全隔离 |
| 脉冲提前结束 | 时长、后续命令、禁用和断连策略 | 对照活动记录及所有命令来源，普通命令可取消计时 |
| `waiting_network` | 所选上行接口是否有可用 IPv4 | 仅 AP 连接不满足 TCP/KNX/MCP 条件 |
| RTU 超时 | 站号、波特率、校验、A/B、终端电阻和当前模式 | 从读取开始，检查 CRC、帧计数和主站接线 |
| TCP 超时 | 模式、上行地址、端口、对端限制、防火墙 | 确认路由及客户端数量，空闲连接 60 秒后关闭 |
| KNX 编辑冲突 | 最新修订号和所有权 | 重新加载并协调改动，不要覆盖 ETS 下载 |
| KNX 出现 401、控件禁用 | 浏览器认证失效 | 重新登录并读取快照，见[网页接管示例](knx-address-entry.md#taking-over-for-web-editing) |
| HA 实体缺失或陈旧 | MQTT 启用/连接、发现、前缀、代理 ACL | 检查保留发现信息和 HA birth 主题，见 [HA](home-assistant.md) |
| MCP 菜单缺失 | 实际镜像与嵌入界面的功能 | 版本字符串不能唯一确定编译功能，核对镜像身份 |
| MCP 等待时间或重试 | NTP、DNS、上行、端点 | 查阅[MCP 运行排错](xiaozhi-mcp.md#runtime-and-troubleshooting)，不要关闭 TLS 验证 |
| GitHub 更新列表异常 | 运行版本、GitHub 连通性/限流及发布文件 | URL 问题在 0.6.4 已修复，但文件匹配仍宽泛；使用核对后的手动 `_ota.bin` |
| RGB 测试不可见或无声音 | 启用状态及优先级 | 故障/编程/复位可覆盖测试，蜂鸣器须启用 |

## 配置与恢复边界 { #configuration-and-recovery-boundaries }

执行器、KNX、MCP 使用带验证的多代存储。通用网络、用户及框架集成设置仍原地写 JSON，掉电可靠性不同；这只是源码结论，不是完成了掉电验证。私下保留网络、用户、继电器策略、集成及 KNX 关联记录。

嵌入式界面的手动 OTA 设计上保留文件系统配置，但不能代替备份。上传文件系统、全擦除、不兼容降级或恢复出厂可能丢失设置。更新前保存镜像身份、对应 ELF，并准备本地恢复方式。

恢复出厂清除用户设置和 KNX 调试数据，保留制造设置身份。BOOT 长按十秒同样有效，禁用点击动作不会禁用长按。恢复后用本机私有密码重新配置。固件无法启动时，隔离负载，按板卡支持的 USB 下载方式和[首次刷写说明](gettingstarted.md#3-build-and-flash-a-unit)恢复。刷写属于主动维护，不是诊断读取。

## 有效的问题报告 { #useful-support-report }

提供板卡版本、固件版本/哈希、浏览器版本、当前协议、脱敏截图、预期与实际行为、复现步骤，以及模拟器中是否出现。附故障码、计数和时间戳，但删除网络密码、令牌、二维码标签、端点查询参数和非必要身份信息。已知问题应链接相关源码审查，而不是直接断言硬件故障。
