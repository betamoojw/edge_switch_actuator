# 裝置操作

入口 `/device` 提供 Outputs、Indicators、Button、Protocol Interface、KNX 及 Maintenance 分頁。可操作項目由登入帳號權限與編譯功能決定。實機畫面見[介面導覽](interface-tour.md)，連線方式見[初次使用](quick-start.md)。

## 輸出控制 { #outputs }

介面以 **1–6** 標示通道。每路都有啟用、開機狀態、名稱、脈衝時間與斷線關閉逾時設定。停用的通道強制 OFF；鎖定的通道不接受一般繼電器命令，須由安裝人員或管理員解除。脈衝依儲存時間執行，到期強制 OFF；後續接受的一般命令會取消計時。

網頁的全部 ON/OFF 會先檢查所有啟用通道；任一路被鎖定或無權操作，就拒絕整筆命令。停用通道維持 OFF。狀態與事件快照代表已下達命令，並非接點量測值。

預設開機為 OFF。改為 ON 即會改變重啟後的輸出。KNX 完成設定後，請於 KNX 區域調整繼電器參數。遇到修訂版本衝突時，重新載入並整合修改。通道旁的 `startup` 是最後命令來源，開機行為須查看儲存的設定。

## 通訊協定選擇 { #protocol-selection }

| 模式 | 條件與行為 |
| --- | --- |
| Off | 停止現場總線；網頁及已啟用的 MQTT/MCP 仍可使用 |
| Modbus RTU | 須啟用 RS485；預設站號 1、19200 baud、8E1 |
| Modbus TCP | 選定上行介面須有 IPv4；預設連接埠 502，可限制單一精確 IPv4 對端 |
| KNX/IP | 選定上行介面須有 IPv4；需設定個別位址、群組位址與參數 |

一次僅能啟用一種總線。`waiting_network` 代表等待上行連線，不是儲存失敗；只有設定 AP 連線並不足夠。詳見 [Modbus](actuator-modbus-map.md) 與 [KNX](knx-address-entry.md)。

斷線關閉預設停用。TCP/KNX 依選定上行介面中斷後的逾時判定，並非偵測特定主站或電文流。RTU 須啟用總線看門狗，以無通訊活動時間判定。單純 MQTT/MCP 斷線不會讓輸出自動 OFF。

## 按鍵與指示功能 { #button-and-indicators }

單擊、雙擊及三擊可分別指派；預設是無動作、識別、切換 KNX 程式設定模式。繼電器目標 0 代表全部啟用通道，1–6 指定單一路。本機按鍵會略過鎖定或停用通道。停用應用按鍵動作，仍不會取消長按恢復原廠設定。

去彈跳時間為 30 ms，短按最長 700 ms，放開後間隔 350 ms 判定組合。按住 5 秒進入重設預備狀態，10 秒執行原廠重設。開機時若已按住，必須先放開才接受手勢。

RGB 顯示優先序為：重設預備、故障、KNX 程式設定、手動識別或測試、上行已連線、AP 設定、等待或連線中。RGB 必須啟用，手動測試限 1–30 秒。蜂鳴器須啟用，測試範圍為 500–4000 Hz、10–2000 ms、工作週期 1–50%。確認提示音只會停止聲音，不會排除原始故障。

## 存取角色 { #access-roles }

| 角色 | 致動器權限 |
| --- | --- |
| Viewer | 通過認證後讀取狀態及組態 |
| Operator | 執行操作命令；通道遮罩限制繼電器寫入 |
| Installer | 操作、組態、協定及 KNX 設定、解除鎖定、Modbus 寫入時窗 |
| Administrator（`admin` 旗標） | 所有通道，另含使用者、網路、整合管理、重設與更新 |

通道遮罩不是框架通用的授權機制；框架設定通常需管理員。MQTT 使用代理 ACL，MCP 另有開放通道遮罩，皆不沿用瀏覽器帳號的通道權限。

## 維護與故障判讀 { #maintenance-and-fault-interpretation }

在 **System → Firmware Update** 手動上傳相符的 `_ota.bin`，先閱讀[更新指南](buildprocess.md)。本板型停用深度睡眠。

| 故障碼 | 原始碼定義 |
| --- | --- |
| 0 | 沒有記錄中的作用中故障 |
| 1 | 蜂鳴器 PWM 配置失敗 |
| 2 | 致動器儲存組態無效，已載入預設值 |
| 3 | 通訊協定初始化失敗 |
| 4 | 原廠重設標記或清理失敗 |
| 5 | KNX 持久化失敗；重試成功後清除 |
| 6 | KNX 應用參數無效 |

請一併查看 `error`、協定狀態與記憶體內的稽核紀錄。恢復原廠會清除可重設組態及 KNX 設定，但保留製造時的設定密碼。若需移除 Home Assistant 保留的探索訊息，應趁代理仍可連線時先停用探索，再移除或重設裝置，詳見[生命週期](home-assistant.md)。
