# 参与贡献

先阅读[架构](architecture.md)和[当前源码审查](actuator-source-review.md)。产品目标为 `waveshare-relay-6ch`；通用框架板型的回归测试不能证明六路硬件行为。

1. 从最新 `dev` 开始，保留无关改动，明确本次解决的问题和行为变化。
2. 界面开发先用[模拟器](frontend-testing.md)，再核对源码契约；检查布局不需要操作实物继电器。
3. 继电器变更应由执行器任务处理，保留启用/锁定检查、传输权限、修订处理和有界重试机制。
4. 执行[验证记录](validation.md#reproduce-software-checks)中的相关检查。固件改动须构建受影响目标并检查真实镜像大小；前端改动须通过类型、模拟器及适当的浏览器测试。
5. 行为变化时同步更新三种语言的用户指南和 API 示例，标明源码推导、模拟、历史记录或硬件测量的证据类型。
6. 提交聚焦的 PR，说明触发条件、修改前后行为、测试结果、剩余风险及有用截图。不要提交凭据、原始设置标签、私有端点或无关生成固件。

文档改动须遵循[发布流程](documentation.md)，运行严格构建，检查桌面和移动端，以及三种语言的覆盖、链接和搜索。为图片提供有意义的替代文本和说明；截图美观并不是验证结果。保留[上游归属](index.md#project-and-license)及许可证，历史设计保留原始背景，不得悄然改成当前操作规范。
