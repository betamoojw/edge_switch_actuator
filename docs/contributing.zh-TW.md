# 參與貢獻

請先參閱[系統架構](architecture.md)及[目前原始碼審查](actuator-source-review.md)。產品目標是 `waveshare-relay-6ch`；一般框架板型可用於回歸測試，但不能證明六路實體硬體的行為。

1. 以最新 `dev` 為基礎，保留其他工作，清楚說明要解決的問題與預期行為。
2. 介面開發先使用[模擬器](frontend-testing.md)，再核對原始碼契約；確認版面不需要切換實體繼電器。
3. 由致動器工作任務統一處理繼電器變更，保留啟用/鎖定檢查、通訊權限、修訂檢查及有界重試。
4. 執行[驗證紀錄](validation.md#reproduce-software-checks)中適用的檢查。韌體變更須編譯受影響目標並檢查實際映像大小；前端變更須進行型別、模擬器與適當的瀏覽器測試。
5. 行為有異動時，同步維護三種語言的操作指南及 API 範例，區分原始碼推導、模擬結果、歷史紀錄與實機量測。
6. PR 應聚焦問題，交代觸發條件、變更前後行為、驗證結果、剩餘風險及必要截圖。勿提交認證資料、原始設定標籤、私有端點或無關的產出韌體。

文件改動請遵循[發佈流程](documentation.md)，執行嚴格建置，檢查桌面與行動版，以及三種語言的覆蓋率、連結與搜尋。圖片需有清楚的替代文字及說明；畫面精美不等於通過測試。保留[上游歸屬](index.md#project-and-license)與授權聲明，歷史設計應保留原本脈絡，不得直接當成現行操作規範。
